# Plan 10: Agent Ops (Governance, Tracing, Deployment) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every verify request traceable (request id, JSON logs, OpenTelemetry spans, audit row), enforce the real Gemini daily cap across restarts, govern the agents with a tested registry and policy map, and ship a demo-on-demand deployment (Docker stack, always-on read API, hosted frontend, recording runbook).

**Architecture:** A small `app/ops/` package holds the request context, JSON logging, run record, tracing helpers and audit writer. ADK's built-in OpenTelemetry spans are exported over OTLP to Phoenix; custom spans cover what ADK cannot see. The shared Gemini counter is charged in-process and persisted by write-behind. A Supabase Edge Function serves `recent` and `result by id`; the heavy backend runs locally in Docker Compose.

**Tech stack:** Python 3.12, FastAPI, Google ADK 2.12, OpenTelemetry (SDK already installed; add the OTLP/HTTP exporter), Supabase (Postgres, Edge Functions on Deno), React/Vite frontend, Docker Compose, Phoenix, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-20-plan10-design.md`. Read §2 (facts), §4 (decisions D1–D12) and §6 first. Decision ids below (D3b, D8, …) refer to it.

## Global constraints

- `uv` only (`uv add`, `uv run`); from the repo root use `uv run --project backend ...`. Never hand-edit dependencies.
- The scoring engine (`backend/app/scoring/`) is untouched. Bias labels come only from AllSides. Confidence capping stays. English only.
- Defaults: `gemini_daily_request_budget = 400`; `quota_reset_tz = "America/Los_Angeles"`; `retention_days = 90`; the read API sends `Cache-Control: public, max-age=60`; request ids match `^[A-Za-z0-9._-]{1,64}$`.
- Trace content (claim, prompt, response text) is **off** unless `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` is set. Keys are never logged, traced or stored in an audit row.
- Every new table has RLS enabled with no policies, and `EXECUTE` on every new function is revoked from `PUBLIC`, `anon`, `authenticated`. Migrations are applied by the project lead by hand, in order (08, then 09).
- Default test runs are offline and make no network calls. The only live (quota-spending) step is Task 13, and it needs the lead's approval in chat with the estimate.
- Never commit `.env`, `*-handoff.md`, `AGENTS.md`, `.claude/`, `.agents/`.
- Work touching agents, scoring, guardrails or eval ends with `code-reviewer` and `eval-guardian` (Task 15).

## Review focus

1. **Overspend after a restart or a database outage.** A restart mid-day keeps the count; an unreachable `daily_usage` never turns the budget into "unlimited" (Tasks 1–2).
2. **Hostile or malformed `X-Request-Id`** (newline, 10 KB, unicode) is replaced, never logged raw, never set as a response header (Task 3).
3. **Leakage.** A sentinel claim string and a fake API key never appear in log lines, spans or audit rows with content capture off (Tasks 3, 5, 6).
4. **Audit completeness without breaking the response.** Cache hit, degraded run, budget refusal and all-agents-failed each write one row; an audit write failure never changes the HTTP response (Task 6).
5. **Hosted site with the backend off.** Empty feed, unknown id, invalid UUID and an Edge Function outage each render a designed state, not a blank page (Tasks 9–10).
6. **The Pacific day boundary and DST change** roll the counter at the right instant (Task 1).
